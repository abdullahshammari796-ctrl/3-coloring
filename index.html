What is Graph 3-Coloring?

Given an undirected graph G = (V, E), can we color every vertex using at most 3 colors so no two adjacent vertices share a color? This is NP-complete.

🎨 Here's the idea in one sentence: Color a map using only 3 crayons, where neighbors can't share a color. That's it!

Let's make it simple with pictures:

Countries next to each other need different colors so you can tell them apart.

Touching countries must be different colors. That's the only rule!

Algorithms

How Does the Computer Try to Solve This?

  • Greedy — O(V+E) heuristic, may use >3 colors.
  • Backtracking — O(3^V) exact solver with pruning.
  • Brute Force — Tries all 3^n assignments.
  • Compare — Side-by-side view.

There are 3 main ways the computer tries to solve this. Pick one to learn:

🐰
Greedy — The Fast One
Goes through the dots one by one and picks the first color that works. Super quick, but sometimes makes mistakes and uses too many colors.
🍽️
Like seating dinner guests: You point at each empty chair one by one and say "you sit here!" — fast, but you might end up with friends at opposite ends of the table.
🧩
Backtracking — The Smart One
Tries a color, checks if it works. If not, goes back and tries another. Always finds the right answer — but takes more time.
🗺️
Like a maze: You pick a path. If you hit a dead end, you walk back and try a different path. You always get out eventually!
🐢
Brute Force — Try Everything
Tries every single possible combination. It WILL find the answer... if you're willing to wait a very long time.
🔐
Like cracking a lock: Try 001, 002, 003, 004... all the way to 999. You'll open it eventually, but it might take hours!

Key Insight: Greedy is polynomial but approximate. Backtracking is exponential but exact. This trade-off is fundamental to NP-completeness. 🎯 The Big Idea in Plain English:
🐰 Fast method = sometimes wrong
🧩 Correct method = sometimes slow
🤷 Nobody has found a way to be BOTH fast AND always correct. That's the biggest unsolved mystery in computer science!

CLO-5: NP-Completeness Proof CLO-5: Why Is This Problem So Hard?
🧠 Ever wonder why some problems are really hard for computers? This section explains it in a fun way — no complex math, just simple ideas!

Step 1: 3-Coloring ∈ NP

🎭 Easy to Check, Hard to Find

Certificate: c: V → {1,2,3}. Verifier: Check c(u)≠c(v) for all edges — O(|E|). ✓

🧩
Jigsaw puzzle analogy: Looking at a finished puzzle and saying "yes, this looks right" — easy. But putting together a 1,000-piece puzzle from scratch? Hard!

It's the same with 3-coloring:

✅
Checking = Easy
Give me a colored map, I'll check every border in seconds.
❌
Finding = Hard
Figuring out the coloring yourself? That could take years!

Step 2: 3-SAT ≤ₚ 3-Coloring

🔗 It's Connected to Another Hard Puzzle

Given a 3-SAT formula φ, build graph G with truth-setting gadget, variable gadgets, and clause gadgets.

Scientists proved something really cool: if you could solve 3-Coloring quickly, you could solve a TON of other hard problems quickly too!

🔗
They're all like puzzles linked by a chain — solve one, solve them all. But nobody has figured out how... yet!

Part A: Truth-Setting Gadget

Triangle (T, F, B) forces 3 distinct colors.

Part B: Variable Gadgets

For each xᵢ: create xᵢ, ¬xᵢ connected to each other and B. One True, one False.

Part C: Clause Gadgets

OR-gadget with 6 aux vertices. 3-colorable iff ≥1 literal True.

Conclusion: 3-Coloring is NP-complete (in NP + NP-hard via 3-SAT reduction). ∎

🏆 3-Coloring is one of the hardest puzzles in computer science. Checking someone's answer is easy, but finding the answer from scratch? Super hard.

💰 Fun fact: There's a $1,000,000 prize waiting for whoever can prove whether this can be solved quickly or not. It's called the "P vs NP" problem. If you solve it, you'll be world famous!
CLO-3: Algorithm Design CLO-3: How Each Method Works
🎓 Let's meet the 4 methods! Each one has a different personality. Pick a favorite!

Greedy Coloring

Paradigm: Greedy — always pick the locally optimal choice. Time: O(V+E). Assigns the smallest available color to each vertex in a given order. The result depends heavily on vertex ordering. Uses at most Δ+1 colors (where Δ is the maximum degree). Limitation: May use more than 3 colors even when a valid 3-coloring exists.

🐰
The Speedy Bunny: Hops through each dot, picks the first color that works, moves on. ⚡ Super fast but sometimes messy!

👉 Pros: Fast.   Cons: Might use too many colors.

Backtracking

Paradigm: Backtracking with constraint propagation. Time: O(3^V) worst case. Try colors 1, 2, 3 for each vertex. If a conflict arises, undo the assignment and try the next color. If all 3 fail, backtrack further. Guarantee: Always finds a valid 3-coloring if one exists, or proves none exists. Pruning makes it much faster than brute force in practice.

🧩
The Careful Puzzle Solver: Tries a color. If it doesn't fit, goes back and tries another. Always finds the answer!

👉 Pros: Always correct.   Cons: Takes more time.

Brute Force

Paradigm: Exhaustive enumeration. Time: O(3^V · E). Generates every possible assignment of 3 colors to V vertices (3^V total), then checks each assignment against all edges. No pruning — every combination is checked. This is the theoretical baseline; backtracking improves on it by pruning invalid branches early.

🐢
The Slow Tortoise: Tries EVERY possible combination, one by one. Very slow, but will definitely find the answer!

👉 Pros: Guaranteed answer.   Cons: Extremely slow for big graphs.

Comparison Mode

Purpose: Runs greedy and backtracking side-by-side on the same graph to demonstrate the trade-off between speed and optimality. Greedy finishes in O(V+E) but may use >3 colors. Backtracking takes O(3^V) worst case but guarantees the minimum. This directly illustrates why NP-complete problems are hard — polynomial heuristics exist but can't guarantee optimal solutions.

Design Trade-off: Greedy = O(V+E), approximate. Backtracking = O(3^V), exact. Brute force = O(3^V · E), exact but no pruning. The gap between polynomial and exponential time is the heart of NP-completeness. 💡 Remember:
🐰 Fast = sometimes wrong
🧩 Correct = sometimes slow
🐢 Try-everything = always slow
🏆 No one has found a "perfect" method yet!
